# 发布与版本管理规范

## 版本号

采用 `MAJOR.MINOR.PATCH`：

- `MAJOR`：不兼容的数据模型、权限或接口变更。
- `MINOR`：新增引擎、主要页面或用户能力。
- `PATCH`：缺陷修复、兼容性修正和文案调整。

首次正式发布为 `1.0.0`。以下位置必须一致：

1. `niudbm/manifest`
2. `server/cmd/niudbm/main.go` 默认版本
3. 前端关于页版本
4. `CHANGELOG.md`
5. 构建产物文件名

## 分支与提交

- `dev`：开发分支。
- `main`：正式发布分支。
- 提交使用 `type: 摘要`，例如 `fix: 修复 MongoDB 配置挂载`。
- 发布前将 `dev` 合并到 `main`，保留合并提交。
- 已发布 tag 不允许移动或覆盖。

## 发布门禁

必须全部满足：

- Go `vet` 与全量测试通过。
- 前端类型检查和生产构建通过。
- `amd64` 与 `arm64` 二进制构建成功。
- 两个 FPK 的架构、静态链接和包内 manifest 校验通过。
- SHA-256 校验文件生成并复核。
- PC 与手机页面检查通过。
- 有 Docker 时完成容器冒烟；无 Docker 时必须明确记录为未执行。
- 真机测试清单完成并归档结果。

## 构建

```bash
scripts/build.sh --pack
```

产物：

```text
dist/niudbm-<version>-amd64.fpk
dist/niudbm-<version>-arm64.fpk
dist/niudbm-<version>-amd64-SHA256SUMS.txt
dist/niudbm-<version>-arm64-SHA256SUMS.txt
```

## GitHub 标签发布

推送 `vMAJOR.MINOR.PATCH` 格式的标签后，`.github/workflows/tag-release.yml` 自动执行：

1. 校验标签版本与 `niudbm/manifest` 一致。
2. 运行后端静态检查、全量测试和前端生产构建。
3. 下载并校验飞牛官方 `fnpack`。
4. 构建 `amd64` 与 `arm64` 两个 FPK。
5. 上传构建产物并创建 GitHub Release。

```bash
git tag -a v1.0.1 -m "牛库管家 v1.0.1"
git push origin v1.0.1
```

标签只允许指向已经通过发布门禁的提交。工作流失败时应修复问题并使用下一个补丁版本重新发布，不移动已推送的标签。

## 数据兼容

- 升级不得删除现有实例、账号、备份和审计。
- 元数据库迁移必须幂等。
- 重大数据模型变更需先备份 `var/niudbm.db`。
- 正式发布后不承诺直接降级。

## 发布说明

面向用户的更新说明保持 3 到 5 条，描述可见结果，不写内部重构、任务号或未完成能力。
