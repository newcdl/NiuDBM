# 牛库管家 v0.1.2 真机测试清单 · M1 部署闭环

> 适用包：`niudbm-0.1.2-amd64.fpk`（x86 机器）、`niudbm-0.1.2-arm64.fpk`（ARM 机器）
> 上一版：0.1.1（M0 瘦身）。本版是 M1「部署闭环」的第一个真机可测版本。
> 目标：确认「装得上 → 建得出服务 → 客户端连得上 → 数据落在你看得见的地方 → 删得干净」这条主线在飞牛 fnOS 上成立。
> 走法：第 2、3 节是 P0，决定这一版能不能用；第 4 节是这一版修掉的三个真实缺陷，必须逐条验；第 5 节列的是**故意没做**的，不算缺陷。

---

## 1. 这一版交付了什么

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 部署向导四步 | 新 | 版本 → root 密码 → 存储 → 资源与端口，每一步各自拦错，不用提交后才发现参数不合法 |
| 部署进度五段 | 新 | 检查版本与端口 / 拉取镜像 / 启动并等待就绪 / 初始化账号与系统库 / 完成 |
| 失败留现场 | 沿用 | 部署失败不收拾干净：容器只停不删，目录与日志都留着，可看部署日志后删掉重来 |
| 连接信息 | 改 | 主机给局域网可连的 IPv4（不再是 `0.0.0.0`）；端口、账号、密码、初始库一次给全 |
| 数据落盘 | 改 | 默认宿主机目录（路径可见可复制），也可选 Docker 命名卷 |
| 容器重启策略 | 新 | `unless-stopped`：NAS 重启后服务自己回来，手动停的不会被拉起 |
| 删除语义 | 修 | 「保留数据」只删容器留卷；「删除数据」连命名卷一起删 |
| 镜像页 | 只读 | 只能列出本地已有的 MySQL / MariaDB 镜像，**没有拉取/导入/删除入口**（见第 5 节） |

安装包很小（约 6MB）：引擎不进包，跑的是 Docker 官方镜像。

## 2. P0 主线：从装好到连得上（约 15 分钟）

| # | 步骤 | 预期 |
| --- | --- | --- |
| 2.1 | `uname -m` 确认架构：`x86_64` 装 amd64 包，`aarch64` 装 arm64 包 | 架构对上 |
| 2.2 | 应用中心手动安装 fpk（老用户直接升级 0.1.1 → 0.1.2） | 安装成功，桌面出现图标；升级路径不要求卸载 |
| 2.3 | 打开应用 → 概览 | 正常渲染；自检区 Docker 显示可用。若显示不可用，先看第 4.1 条 |
| 2.4 | 「镜像」页 | 列出本机已有的 MySQL/MariaDB 镜像（首次可能是空的，正常，不算缺陷） |
| 2.5 | 「数据库」→ 部署服务 → 第 1 步选版本（如 8.4） | 只列当前架构支持的官方 tag |
| 2.6 | 第 2 步：点「生成」拿到 root 密码，或手填（≥8 位）；点复制 | 密码能复制走；短密码在本步就被拒 |
| 2.7 | 第 3 步：存储选「宿主机目录」，路径填一个**你自己**的绝对路径（如 `/vol1/mysql/smoke`） | 输入框提示留空则用应用数据目录 |
| 2.8 | 第 4 步：端口**故意填一个已被占用的**（先用系统里别的服务占着），点部署 | 当场被拒并说明端口被占用，**不会**挂一个注定失败的任务 |
| 2.9 | 端口改回自动分配，资源选默认，确认部署 | 进度条依次走完五段；每段显示正在做什么；总耗时几十秒到几分钟（首次拉镜像更久） |
| 2.10 | 部署完成后点进服务详情 → 连接信息 | 主机是 `192.168.x.x` / `10.x.x.x` 这类局域网地址，**不是** `0.0.0.0`、**不是** `127.0.0.1` |
| 2.11 | 一键复制连接信息，用 DBeaver / Navicat / 手机客户端连 | 能连上；账号是服务里建的业务账号，不是 root |
| 2.12 | 详情页建一个库、建一个只读账号，用该账号连接 | 只读账号能 `SELECT`，`INSERT` 被拒（1142） |

## 3. P0 存储与删除语义（约 10 分钟，会动 Docker 数据）

> 这一节要 SSH 到 NAS 上执行几条 `docker` 命令。普通用户没有 docker 权限就先 `sudo -i`。

| # | 步骤 | 预期 |
| --- | --- | --- |
| 3.1 | 对 2.7 那个 bind 存储的服务，在 NAS 上 `ls -l /vol1/mysql/smoke` | 目录真实存在，里面是 MySQL 的数据文件（不是空的） |
| 3.2 | 界面上看该服务的存储路径与体积 | 路径能复制；体积能算出非零值（不是「卷内」） |
| 3.3 | `docker inspect mysql-8.4-<端口> --format '{{.HostConfig.RestartPolicy.Name}}'` | 输出 `unless-stopped` |
| 3.4 | 再部署一个服务，存储选「Docker 命名卷」 | 部署成功；界面上体积显示「卷内」（命名卷宿主统计不到，属预期） |
| 3.5 | `docker volume ls \| grep niudbm-` | 能看到 `niudbm-<实例id小写>-data` |
| 3.6 | 删除这个卷存储的服务，删除对话框选「**保留数据**」 | 服务从列表消失；容器已删除；`docker volume ls` 里**卷还在** |
| 3.7 | 重新部署一个卷存储服务，这次删除选「**删除数据**」 | 容器删除；`docker volume ls` 里该卷**消失** |
| 3.8 | 删除一个 bind 存储的服务（选删除数据） | 容器删除；应用数据目录被回收；**你自己填的宿主机目录里的数据保留**，界面会提示「宿主目录未删除，请按需自行清理」 |

## 4. P0：这一版修掉的三个缺陷，逐条验

| # | 验什么 | 怎么验 | 通过标准 |
| --- | --- | --- | --- |
| 4.1 | Docker 权限（0.1.1 的坑） | 概览/自检页看 Docker 状态；若报不可用，按提示里的命令核对 socket 属组 | 应用用户已在 docker 组内，自检显示可用；报错时给出的属组与修复命令与 `ls -l /var/run/docker.sock` 一致 |
| 4.2 | 连接地址不是监听地址 | 见 2.10 | 复制出来的是能连通的局域网 IP |
| 4.3 | 容器异常退出后自愈 | 在 NAS 上 `docker kill mysql-8.4-<端口>`，等 10~30 秒，`docker ps` | 容器被自动拉起，服务恢复可用（除非你在界面上手动停过它） |
| 4.4 | 手动停的不被拉起 | 界面上把服务停掉 → 重启 NAS（或重启应用）→ 回来看 | 仍然显示「已停止」，没有被偷偷拉起 |
| 4.5 | 部署进度不回退 | 2.9 的全过程盯住进度条 | 五段只往前走，最后一段不会跳回第一段 |
| 4.6 | 删除后数据真的按选择处理 | 见 3.6 / 3.7 | 保留数据时卷在，删除数据时卷没了 |

## 5. 这一版故意没做（不要当缺陷报）

- **镜像页只有列出**：没有「拉取」「导入 tar」「删除镜像」「被几个服务使用」这些入口，M1 的第二批交付里做。
- **没有容器健康检查与状态灯**：`mysqladmin ping` 探活、异常高亮、启动超时自定义重试都还没做。
- **没有连接二维码**：手机连库目前靠复制粘贴。
- **重启策略不可在设置里改**：固定 `unless-stopped`。
- **没有概览仪表盘、日志页、参数页、用户页之外的新页面**。
- **引擎版本不随包升级**：镜像 tag 就是版本，换版本 = 新建服务搬数据。

## 6. 出包前已经跑过的验证（不用重做）

- `gofmt` 无差异、`go vet`、`go test -count=1 ./...` 全绿
- 容器内冒烟（`SMOKE_DOCKER=1 scripts/smoke.sh`，真 Docker + 真 MySQL 8.4）13 项全绿，其中包括：
  - 部署失败留现场：非法初始化 SQL → 状态 failed、原因可读、部署日志可下载、删掉后目录回收
  - 真实 TCP 密码认证下的四档权限（1045 / 1142 / 1044）
  - 连接信息 `host` 不是 `0.0.0.0`；默认存储是 `bind` 且 `filePath` 目录真实存在
  - 命名卷两个方向：`keepData=false` 卷消失、`keepData=true` 卷仍在
  - 备份 → 改数据 → 恢复 → 数据一致；删除实例后容器与目录都回收
- **没有做的**：真机浏览器回归、手机端布局、双架构实机安装。这些正是这份清单要你补的。

## 7. 记录方式

每条失败按这个格式回我，能直接定位：

```
编号：3.6
期望：选「保留数据」后 docker volume ls 里卷还在
实际：卷没了，服务列表也空了
日志：/var/apps/niudbm/var/instances/<实例id>/deploy.log 末 20 行（或界面「查看部署日志」）
```

有疑问的项先记下来，别自己绕过——绕过会掩盖问题。
