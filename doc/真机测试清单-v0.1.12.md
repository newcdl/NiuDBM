# 牛库管家 v0.1.12 真机测试清单 · 配置文件补齐

> 适用包：`niudbm-0.1.12-amd64.fpk`（x86）、`niudbm-0.1.12-arm64.fpk`（ARM）
> 直接覆盖 0.1.11，不用卸载。
> 只验一件事：**配置文件是不是一份完整、正确、随服务存在的配置**。

---

## 1. 为什么之前只有几行（先说结论）

| 原因 | 说明 |
| --- | --- |
| 保存只写改动项 | `ApplySettings` 只把本次改动的 key 写回文件，没改过的不会补 |
| 部署时根本不生成 | `ensureCnf` 没有调用点，文件是第一次保存参数时才有 |
| 字符集参数被命令行覆盖 | 启动时传了 `--character-set-server`，优先级高于配置文件 |

这一版三条都改了，下面按顺序验。

## 3. 老服务：缺项提示与补全

| # | 步骤 | 预期 |
| --- | --- | --- |

## 4. 字符集与排序规则（本版新增的坑）

| # | 步骤 | 预期 |
| --- | --- | --- |
| 4.1 | 配置页找「服务端排序规则」 | 在「服务端字符集」下面，默认 `utf8mb4_unicode_ci` |
| 4.2 | 只把字符集改成 `latin1` → 保存 | 报错「字符集 latin1 与排序规则 utf8mb4_unicode_ci 不匹配：改字符集时请一并改排序规则」 |
| 4.3 | 两者一起改（latin1 + latin1_swedish_ci）→ 保存 → 重启 | 重启成功；`SHOW VARIABLES LIKE 'character_set_server'` 是 latin1 |
| 4.4 | 改回 utf8mb4 + utf8mb4_unicode_ci → 重启 | 正常 |
| 4.5 | 验证"改了不再被启动参数盖掉" | 4.3/4.4 能生效即证明（旧版会被容器启动参数覆盖，改了等于没改） |

## 5. 版本差异

| # | 场景 | 预期 |
| --- | --- | --- |
| 5.1 | MySQL 8.0 服务 | 有 `default_authentication_plugin`，也有 `innodb_redo_log_capacity` |
| 5.2 | MySQL 5.7 服务（x86 机器） | 有 `default_authentication_plugin`，**没有** `innodb_redo_log_capacity`；排序规则默认 `utf8mb4_general_ci` |
| 5.3 | MariaDB 服务 | 有 `aria_pagecache_buffer_size`；没有 `innodb_redo_log_capacity`；没有 `default_authentication_plugin` |
| 5.4 | 任意版本改参数 | 只能看到/改到本版本存在的项，不存在的项保存会被拒并说明原因 |
