# 牛库管家 v0.1.10 真机测试清单 · 配置页可直接改配置文件

> 适用包：`niudbm-0.1.10-amd64.fpk`（x86）、`niudbm-0.1.10-arm64.fpk`（ARM）
> 直接覆盖 0.1.9，不用卸载。
> 只验一件事：**能不能在界面里直接改 my.cnf，改坏了能不能退回去**。

---

## 1. 入口与读取

| # | 步骤 | 预期 |
| --- | --- | --- |
| 1.1 | 服务 → 配置 | 「可调参数」下面多出一张「配置文件（高级）」卡片 |
| 1.2 | 卡片内容 | 顶部一排按钮（重新载入 / 恢复上一版 / 重启生效 / 保存配置文件）+ 一段说明 + 等宽编辑器 + 底部行数提示 |
| 1.3 | 编辑器内容 | 是当前 `conf/niudbm.cnf` 的原文，形如 `[mysqld]` + 若干 `key = value` |
| 1.4 | 说明里的路径 | 显示真实绝对路径，鼠标能选中复制 |
| 1.5 | 点「重新载入」 | 丢弃未保存改动，重新从磁盘读一遍 |
| 1.6 | 从未保存过参数的新服务 | 「恢复上一版」是灰的（没有上一版），底部不显示"本机已存有一版备份" |

## 2. 写一个界面上没有的参数

> 选一个白名单里没有、且安全可改的参数，例如 `innodb_page_size`（需重建实例才彻底生效，仅作演示）或 `max_connect_errors`。

| # | 步骤 | 预期 |
| --- | --- | --- |
| 2.1 | 在编辑器里加一行 `max_connect_errors = 2000` | 右上角出现「未保存」标记，底部提示"有未保存的改动" |
| 2.2 | 点「保存配置文件」 | 弹出确认框，说明会覆盖并有备份、写错可能起不来 |
| 2.3 | 取消 | 什么都没变，「未保存」仍在 |
| 2.4 | 再点保存 → 确认 | 提示"配置文件已保存，重启服务后生效"；卡片里出现「重启生效」按钮；「未保存」消失；底部显示"本机已存有一版备份" |
| 2.5 | 点「重启生效」→ 确认重启 | 服务重启，之后用客户端执行 `SHOW VARIABLES LIKE 'max_connect_errors';` 应是 2000 |
| 2.6 | 再进配置页 | 编辑器里仍有那行，参数区里若该参数在白名单内也会显示新值 |

## 3. 校验与拦截

| # | 步骤 | 预期 |
| --- | --- | --- |
| 3.1 | 把编辑器清空 → 保存 | 后端拒绝："配置文件不能为空：留空会导致实例启动失败" |
| 3.2 | 只留空白字符 → 保存 | 同上 |
| 3.3 | 贴入超过 64KB 的文本 → 保存 | 拒绝："配置文件超过 64KB，请确认没有误粘贴" |
| 3.4 | 贴入一段 SQL 脚本（没有 `[mysqld]` 之类的段头）→ 保存 | 被形状检查拒绝，提示缺 section |
| 3.5 | 正常内容里用中文注释 | 能保存（注释不影响解析） |

## 4. 恢复上一版（关键保命路径）

| # | 步骤 | 预期 |
| --- | --- | --- |
| 4.1 | 接 2.4，把 `max_connect_errors` 改成 `1`（可能让连接频繁被拒）→ 保存 → 重启 | 服务起来后连接异常，符合预期（说明真写进去了） |
| 4.2 | 回配置页 → 点「恢复上一版」 | 确认框："会用上一版覆盖当前配置文件，当前的改动会丢失" |
| 4.3 | 确认 | 提示"已恢复上一版配置，重启服务后生效"，编辑器内容回到改之前（`max_connect_errors` 变回 2000 或初始状态） |
| 4.4 | 点「重启生效」 | 服务正常，`SHOW VARIABLES` 回到上一版的值 |
| 4.5 | 故意写坏（如 `innodb_buffer_pool_size = abc`）→ 保存 → 重启 | 服务起不来（容器退出）；用「恢复上一版」+「重启生效」应能救回来 |
| 4.6 | 服务起不来时还能打开配置页吗 | **需要重点确认**：实例未运行时配置页是否仍能读取与保存配置文件（后端不检查运行状态，预期可用）；如果页面报错打不开，记录下来 |

## 5. 与「参数」区的关系

| # | 步骤 | 预期 |
| --- | --- | --- |
| 5.1 | 手写加一行注释和一个 `[client]` 段（如 `default-character-set = utf8mb4`） | 能保存 |
| 5.2 | 回到「可调参数」，改一个参数并保存 | 保存成功，但**手写的注释与 `[client]` 段会丢**（文件被整份重写），界面上有这条提醒 |
| 5.3 | 再进配置文件卡片 | 只剩参数区写入的 `key = value`，头两行是新的引导注释 |

## 7. 出包前跑过的验证

- 前端 `vue-tsc --noEmit` + `vite build` 通过（1665 modules）。
- 后端 `gofmt` / `go vet` / `go test -count=1 ./...` 全绿。
- 容器冒烟 20 项全绿，新增 1 项「配置文件原文读写、空内容拦截与恢复上一版」：
  - 读：`backupExists=false`
  - 先用参数页保存一次（让文件存在），再手写 `max_connections = 300` → `needRestart=true`
  - 再读：内容是新写的，`backupExists=true`
  - 写空内容 → 400「不能为空」
  - 恢复上一版 → 手写的 300 消失，回到参数页写的 200
