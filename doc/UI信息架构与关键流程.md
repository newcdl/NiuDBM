# 牛库管家（NiuDBM）UI 信息架构与关键流程

> 配套文档：[产品与技术方案](./牛库管家-NiuDBM-产品与技术方案.md) ｜ [引擎分发与版本策略](./引擎分发与版本策略.md) ｜ [权限与平台核对清单](./权限与平台核对清单.md)
>
> 版本：v1.0 ｜ 目标：让第一次用 NAS 的人，**3 步内拿到可用的数据库连接信息**

---

## 0. 设计目标与原则

### 0.1 一句话目标

用户点开应用后，不需要知道 "实例 / 引擎 / 字符集 / 数据目录" 这些词，也能在 1 分钟内得到一个能连上的数据库。

### 0.2 五条原则

| 原则 | 具体做法 |
| --- | --- |
| **成果前置** | 建库结束时第一眼看到的是「连接信息卡」，而不是又一个列表 |
| **默认即正确** | 引擎版本、字符集、端口、资源档位全部预填推荐值，高级项折叠 |
| **危险分级** | 删除、开外网、大版本升级必须"二次确认 + 输入确认词"，其他操作不打扰 |
| **长任务可离开** | 引擎下载、备份、恢复进入任务中心，页面可关，回来能看进度 |
| **错误给出口** | 任何失败都附"下一步能点什么"，不出现裸报错码 |

### 0.3 明确不做的事

- 不做 SQL 全功能 IDE（只提供轻量查询台，P2）
- 不做图表堆砌的仪表盘（NAS 用户不需要 12 个折线图）
- 不做多级嵌套导航（最多两级：列表 → 详情）

## 1. 角色与可见性

### 1.1 三种角色

| 角色 | 判定来源 | 可见范围 | 可执行 |
| --- | --- | --- | --- |
| 管理员 | 网关 Header `X-Trim-Isadmin=true` | 全部实例 | 全部操作，含删库、开外网、改授权 |
| 成员 | 被管理员加入某实例的成员列表 | 仅被授权的实例 | 查看、备份、导入（按授权级别） |
| 访客 | 已登录但未被授权任何实例 | 空态页 + 申请入口 | 无（只可提交申请） |

### 1.2 关键判断

数据库实例是 **NAS 级共享资源**，不是个人文件。因此：

- 默认**不按 uid 隔离**，而按"实例成员"授权；
- 普通用户登录后看到的是"我被允许访问的库"，而不是"我建的库"；
- 所有实例页面顶部标注归属与成员数，避免误以为是自己独占。

## 2. 信息架构

### 2.1 导航结构（两级）

下面是 **v0.3.0 已实现**的结构（以代码为准）：

```
牛库管家
├── 概览                 ← 默认落地页
├── 数据库               ← 实例列表（核心）
│   └── 实例详情
│       ├── 概览（状态 / 连接信息 / 版本 / 目录 / 创建时间）
│       ├── 配置（按引擎区分：PG 走 ALTER SYSTEM，MariaDB 写 my.cnf 后重启，SQLite 走 PRAGMA）
│       ├── 用户（PG / MariaDB 四档权限；SQLite 提示文件权限）
│       ├── 备份与恢复
│       ├── 导入导出（SQL 脚本 / CSV）
│       └── 设置（重命名 / 启停 / 删除）
├── 引擎管理             ← 安装 / 修复 / 卸载 / 版本信息
├── 操作记录             ← 审计
├── 任务中心（暂未开放）
├── 设置（暂未开放）
└── 自检                 ← 平台目录与权限体检
```

**刻意不做的页面**：表结构浏览、SQL 控制台。本应用管的是数据库的配置、用户、备份、导入导出与引擎，临时查数请用专业客户端。

下面的 2.2 起保留了早期设计的目标形态，其中“库与表”“日志与慢查询”“下载源与备份目标”“通知与告警”等属于后续规划，尚未实现。

一级导航目前共 6 项（含两个未开放占位），手机端收起为抽屉，避免 iframe 内横向拥挤。

### 2.2 页面清单

| 页面 | 核心任务 | 主要状态 |
| --- | --- | --- |
| 概览 | 一眼看清"有几个库、能不能连、有没有异常" | 空态 / 正常 / 有告警 |
| 实例列表 | 找到某个实例并进入 | 空态 / 列表 / 加载中 |
| 实例详情·概览 | 拿连接信息、看健康度 | 运行 / 停止 / 异常 / 启动中 |
| 实例详情·数据库 | 建库、看表、看体积 | 有库 / 无库 |
| 实例详情·账号 | 建账号、配权限 | 有账号 / 无账号 |
| 实例详情·备份 | 配策略、手动备份、恢复 | 无备份 / 有备份 / 进行中 |
| 实例详情·日志 | 排错 | 有日志 / 空 |
| 实例详情·设置 | 改参数、开外网、删实例 | 常规 / 危险区 |
| 建库向导 | 3 步拿到连接信息 | 步骤态 / 下载中 / 失败 |
| 任务中心 | 看长任务进度与历史 | 进行中 / 已完成 / 失败 |
| 设置各页 | 引擎、源、备份目标、通知 | 常规 |

## 3. 页面设计

### 3.1 概览（落地页）

```
┌────────────────────────────────────────────┐
│  牛库管家                    [任务 2]  [⚙] │
│                                            │
│  3 个数据库运行中        ⚠ 1 个需要关注     │
│                                            │
│  ┌──────────────────────────────────────┐  │
│  │ blog_db          MariaDB 11.4   ● 运行│  │
│  │ 127.0.0.1:33001  · 2 个账号   [连接] │  │
│  └──────────────────────────────────────┘  │
│  ┌──────────────────────────────────────┐  │
│  │ 家庭相册库        PostgreSQL 16  ● 运行│  │
│  │ 127.0.0.1:33002  · 1 个账号   [连接] │  │
│  └──────────────────────────────────────┘  │
│  ┌──────────────────────────────────────┐  │
│  │ 缓存              Valkey 8      ● 运行│  │
│  │ 127.0.0.1:33003               [连接] │  │
│  └──────────────────────────────────────┘  │
│                                            │
│         [ + 创建数据库（主按钮）]           │
└────────────────────────────────────────────┘
```

设计要点：

- **只展示"能不能连"**：地址 + 端口 + 状态点，不做无意义的 QPS 折线。
- 异常实例置顶并给出具体原因（"磁盘剩余 1.2 GB，低于安全线"）。
- 主按钮只有一个，文案用 **"创建数据库"** 而不是"创建实例"（降低理解成本）。
- 顶部常驻任务入口，有进行中任务时显示数量角标。

### 3.2 实例列表

与概览的区别：概览是"卡片速览"，列表是"批量管理与检索"。

| 列 | 说明 |
| --- | --- |
| 名称 / 引擎版本 | 主信息，点进入详情 |
| 状态 | 运行 / 停止 / 异常 / 启动中（带原因） |
| 连接地址 | 默认 `127.0.0.1`，开后显示局域网地址并标注 |
| 库数量 / 账号数 | 快速判断规模 |
| 体积 | 数据目录占用 + 磁盘水位提示 |
| 最近备份 | "2 小时前" / "从未备份"（后者高亮） |

**"从未备份"必须显眼**——这是 NAS 用户最该被提醒的一件事。

### 3.3 实例详情

顶部固定信息条（不随滚动消失）：

```
blog_db  ·  MariaDB 11.4.5  ·  ● 运行  ·  [停止] [备份] [更多 ▾]
```

六个 Tab 的内容侧重：

| Tab | 首屏必须回答的问题 |
| --- | --- |
| 概览 | 怎么连？（连接信息卡 + 一键复制） |
| 数据库 | 有哪些库、多大、谁在用 |
| 账号与权限 | 有哪些账号、各自能访问什么 |
| 备份与恢复 | 上次成功是什么时候、失败过吗 |
| 日志与慢查询 | 最近有没有报错、慢查询 Top 5 |
| 设置 | 参数、网络、危险区 |

### 3.4 建库向导（最关键的三步）

```
步骤 1 / 3  选择引擎       步骤 2 / 3  填名字      步骤 3 / 3  完成
```

**步骤 1：选择引擎（卡片式，不写技术术语）**

```
┌────────────┐ ┌────────────┐ ┌────────────┐
│  建网站     │ │  装应用     │ │  缓存加速   │
│  MariaDB   │ │ PostgreSQL │ │  Valkey    │
│  最常见     │ │  功能更强   │ │  极快      │
│  已就绪 ✓   │ │  需下载 32MB│ │  已就绪 ✓  │
└────────────┘ └────────────┘ └────────────┘
```

- 用场景名做主标题，引擎名做副标题——用户不知道什么是 MariaDB，但知道自己要"建网站"。
- 未下载的引擎直接标体积与预计耗时，避免点了才等。
- 默认高亮"建网站"，因为它对应最大人群。

**步骤 2：只问两件事**

```
数据库名称  [ blog_db          ]   ← 自动校验合法性，实时提示
            ↓ 高级选项（默认折叠）
            字符集（推荐 utf8mb4）· 端口（自动分配 33001）· 数据位置（默认数据卷）
```

**步骤 3：交付成果**

```
✓ 数据库已就绪

  主机   127.0.0.1        [复制]
  端口   33001            [复制]
  数据库 blog_db
  用户名 blog_user        [复制]
  密码   ••••••••••       [显示] [复制]

  [ 复制全部连接信息 ]   [ 生成扫码连接 ]   [ 完成 ]
```

设计要点：

- 密码默认掩码，点"显示"后才明文，且该动作记入审计。
- "复制全部"输出一段可直接贴进配置文件的多行文本（含各字段说明）。
- 扫码连接给手机端/其他设备用，省去手抄密码。
- **不在这里推"下一步做什么"的长引导**，只留"完成"，避免打断。

### 3.5 备份与恢复

- 上方：策略卡片（周期、保留份数、目标位置、上次结果）。
- 中部：备份记录列表（时间、类型、体积、校验状态、[恢复] [下载] [删除]）。
- 下方：恢复入口（恢复前强制提示会覆盖现有数据，并自动生成保护性备份）。

恢复流程必须显示**预计耗时与影响范围**（"该库 2.3 GB，预计 3–5 分钟，期间应用不可用"），而不是一句"确定吗"。

### 3.6 账号与授权

- 左侧账号列表，右侧权限矩阵（库 × 读/写/DDL 三列勾选）。
- 顶部显示"最近使用时间"，长时间未使用的账号标注建议回收。
- 授权矩阵旁提供"生成授权语句"折叠区，给需要手写配置的用户。

### 3.7 任务中心

一条任务 = 一行，包含：类型（下载/备份/恢复/导入）、目标、进度、开始时间、结果、[查看日志]。

失败任务必须展示**可执行建议**，例如：

```
✗ 引擎下载失败
  MariaDB 11.4.5 · 32 MB · 3 分钟前
  原因：无法连接下载源
  [ 重试 ]  [ 更换下载源 ]  [ 导入离线包 ]
```

### 3.8 设置

| 页 | 关键内容 |
| --- | --- |
| 引擎管理 | 已安装版本、可下载版本、离线导入入口、占用空间与清理 |
| 下载源 | 源列表与测速、自定义源、校验公钥状态（只读展示） |
| 备份目标 | 授权目录选择（唤起系统选择器）、MinIO/SMB 配置、连通性测试 |
| 通知 | 站内 / 邮件 / Webhook，附"发送测试消息" |
| 关于与许可 | 版本、引擎许可清单、源码出处、审计日志导出 |

## 4. 关键流程

### 4.1 首次使用（装完第一次打开）

```
打开应用 → 无实例空态 → [创建第一个数据库] → 向导 → 连接信息
```

空态页承担三件事：说明这是什么、给一个默认推荐、给一个"我已有数据库"的入口（走纳管）。

### 4.2 创建实例并建库（含按需下载）

1. 选引擎 → 若本地无对应包，页面直接显示"需下载 32 MB，约 40 秒"并前置确认；
2. 下载中显示进度与"可离开页面，稍后回来"；
3. 下载完成 → 自动继续初始化，用户无需再点；
4. 初始化完成 → 跳到步骤 3 的连接信息；
5. 任何一步失败 → 停在当前步骤，给出三个出口（重试 / 换源 / 导入离线包）。

### 4.3 开启局域网 / 远程访问

```
实例详情 → 设置 → 网络
  当前：仅本机可连（推荐）
  [ ] 允许局域网访问
       └ 选择网段：192.168.1.0/24 [▾]
       └ 提示：开启后同网段设备可连接，请确保已设置强密码
```

- 开关关闭时，页面明确写"仅本机可连"，避免用户误以为外部能访问。
- 打开时**必须展开网段选择**，不允许"一键全开"。
- 远程说明只描述系统已有的访问方式，不引导用户做端口映射。

### 4.4 备份与恢复

见 §3.5。补充：策略创建后立即显示"下次执行时间"，让用户有预期。

### 4.5 导入 SQL

```
选择来源： [系统文件]  [上传文件]
  └ 系统文件 → 唤起系统文件选择器（授权目录内）
  └ 上传文件 → 拖拽/选择，适合拖外部文件
目标库：[ blog_db ▾ ]
预检：编码 utf8mb4 · 预计 1.2 万条语句 · 目标表将新增 6 张
[ 开始导入 ]
```

**预检结果必须先展示再执行**，避免用户把大文件导进错误的库。

## 5. 交互与状态规范

### 5.1 连接信息卡（全产品最重要的组件）

| 状态 | 表现 |
| --- | --- |
| 仅本机 | 显示 `127.0.0.1`，附一行"仅 NAS 本机可连" |
| 已开局域网 | 显示局域网 IP，附"同网段可连" |
| 实例停止 | 地址置灰，提示"实例已停止，先启动再连接" |
| 密码 | 默认掩码，显示/复制均记审计 |

### 5.2 危险操作分级

| 级别 | 操作 | 确认方式 |
| --- | --- | --- |
| 低 | 停止实例、删除备份 | 单次确认弹窗 |
| 中 | 开启局域网访问、修改端口 | 确认 + 影响说明 |
| 高 | 删除实例、删除数据库、大版本升级 | 输入实例名/库名才可继续 + 强制备份 |

### 5.3 空态

每个空态都必须包含：一句解释 + 一个主行动。

| 页面 | 空态文案方向 |
| --- | --- |
| 实例列表 | "还没有数据库。创建一个，1 分钟就能连上。" |
| 备份 | "还没有备份。建议先开一个每日备份，保留 7 份。" |
| 日志 | "暂无日志。实例运行后会在这里生成。" |
| 访客 | "你还没有被授权的数据库。可向管理员申请。" |

### 5.4 失败态与文案

统一结构：**发生了什么 + 为什么 + 你可以做什么**。

| 场景 | 文案 |
| --- | --- |
| 端口冲突 | "端口 33001 已被占用。已为你推荐 33004。" |
| 磁盘不足 | "需要 1.2 GB，当前可用 600 MB。可清理旧备份或换到其他卷。" |
| 引擎下载失败 | "无法连接下载源。可重试、更换源，或导入离线包。" |
| glibc 不满足 | "当前系统库版本过低，MariaDB 11.4 无法运行。建议改用 10.11，或纳管已有实例。" |
| 启动失败 | "实例启动失败。查看日志 →"（附前 5 行关键错误） |

### 5.5 长任务反馈

- 超过 3 秒的操作一律异步，返回任务号并进入任务中心；
- 页面内显示轻量进度条，离开页面不中断；
- 完成后用站内消息提示，失败则附建议动作。

## 6. 视觉与平台约束

### 6.1 iframe / 网关约束

| 约束 | 应对 |
| --- | --- |
| 页面运行在系统网关 `/app/niudbm` 下 | 所有资源用相对路径，禁止写死根路径 |
| 窗口高度由宿主决定 | 使用内部滚动区，避免双层滚动条 |
| 登录态由宿主提供 | 不做登录页、不做登出，用户身份从 Header 获取 |
| 主题/语言由宿主决定 | 跟随深色模式；文案走语言包，不硬编码中文 |
| 文件选择需宿主能力 | 通过系统文件选择器，不实现自研文件浏览器 |

### 6.2 响应式与移动端

- 断点：≥1200 双栏、768–1199 单栏、<768 卡片纵向堆叠；
- 移动端隐藏表格，改为卡片列表（连接信息卡在手机上要能一屏容纳）；
- 触控目标 ≥ 44px，危险按钮不放在拇指误触区。

### 6.3 主题与语言

- 颜色全部走 CSS 变量，深色模式下"危险红"需降饱和，避免刺眼；
- 语言包按 key 组织，禁止在组件里写中文字符串（便于后续英文版）；
- 术语统一：**数据库 / 实例 / 账号 / 备份**，不使用"schema、role、dump"等原词直接面向用户。

### 6.4 无障碍基础

- 所有图标按钮带文本标签（`aria-label`）；
- 状态不只靠颜色区分（状态点 + 文字）；
- 表单错误与输入框关联，键盘可完整操作。

## 7. 文案规范

| 规则 | 反例 | 正例 |
| --- | --- | --- |
| 说人话 | "初始化失败：exit code 1" | "实例启动失败，以下是前几行错误" |
| 给出口 | "网络错误" | "无法连接下载源，可重试或更换源" |
| 量化 | "空间不足" | "需要 1.2 GB，当前可用 600 MB" |
| 不吓人 | "此操作将永久销毁数据！" | "删除后数据无法恢复。建议先备份。" |
| 术语一致 | 同一处叫"实例"另一处叫"服务" | 全产品统一用"实例" |
