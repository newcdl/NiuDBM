> 适用包：`niudbm-0.1.5-amd64.fpk`（x86）、`niudbm-0.1.5-arm64.fpk`（ARM）

## 5. 配置页：状态 + 性能方案

| # | 步骤 | 预期 |
| --- | --- | --- |
| 5.1 | 服务详情 → 配置 | 顶部是「当前状态」，下面是「可调参数」 |
| 5.2 | 看当前状态 | 十六项指标：运行时长、当前连接、累计语句、每秒语句、发送/接收、慢查询、缓冲池命中率、磁盘临时表、无索引 JOIN 等；值不为空 |
| 5.3 | 点「刷新」 | 数值更新（运行时长会增加） |
| 5.4 | 服务停止后再进配置 | 状态区提示"启动服务后可以看运行状态"，参数区仍可看（停止时改配置由后端拦） |
| 5.5 | 优化方案选「4-8GB」→ 点「应用方案」 | 下方 `innodb_buffer_pool_size` 等被填成 4G 档的值，未保存标记出现 |
| 5.6 | 点「保存修改」 | 保存成功，提示里有"需重启才生效" |
| 5.7 | 页脚出现「立即重启生效」 | 点它 → 确认 → 重启，重启后缓冲池值变成新值（再看当前/默认值会变） |
| 5.8 | 参数清单 | 至少能看到：排序缓冲、顺序读缓冲、随机读缓冲、关联缓冲、内存临时表上限、InnoDB 日志缓冲、线程缓存、二进制日志缓存、空闲连接超时、提交刷盘策略、IOPS 基准、慢查询日志文件名 |
| 5.9 | 某项点「填默认值」再保存 | 回到引擎默认值 |
| 5.10 | 填一个非法值（如缓冲池填 `abc`） | 保存时报错，不会写坏配置 |

## 7. 这一版故意没做

- 镜像页仍只能列出本地镜像（拉取/导入/删除在 0.1.6）。
- 没有健康检查状态灯、没有连接二维码。
- 「当前状态」是快照，不是实时图表；要曲线得等后面做监控页。
- 性能方案只给五档内存，不读这台机器的真实内存自动选（会误导，先让人自己选）。
- 直接编辑 my.cnf 原文没有开放（白名单之外随手写坏一个参数，实例就起不来）。

## 8. 出包前跑过的验证

- `gofmt` / `go vet` / `go test -count=1 ./...` 全绿；前端 `vue-tsc` + `vite build` 通过。
- 容器内冒烟（真 Docker + 真 MySQL 8.4）16 项全绿，本版新增：
  - 带 `hosts:["172.16.10.111"]` 建号返回该 IP；PATCH 成两个 IP 后第二个也在
  - `GET /users/{name}/password` 能取回 `SmokePass_Only42`
  - `GET /config/presets` 返回五档（含 `4-8GB`）
  - `GET /status` 返回 `buffer_pool_hit` 等指标
- 账号来源是真 MySQL 账号行：`user@'%'` 与 `user@'172.16.10.111'` 分别建、分别删，改来源不会连带删掉别的来源。
