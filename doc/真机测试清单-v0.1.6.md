# 牛库管家 v0.1.6 真机测试清单 · 连接信息抽屉 + root 掌控

> 适用包：`niudbm-0.1.6-amd64.fpk`（x86）、`niudbm-0.1.6-arm64.fpk`（ARM）
> 直接覆盖 0.1.5，不用卸载；升级后**不需要**重建已有服务。
> 这一版验四件事：连接信息抽屉、root 远程访问开关、root 密码重设、访问来源网段。

## 1. 连接信息抽屉

| --- | --- | --- |

| 1.8 | 概览卡片右上角「容器 / 外部地址 ›」 | 点它同样打开这个抽屉 |

## 2. root 远程访问开关

| # | 步骤 | 预期 |
| --- | --- | --- |
| 2.1 | 抽屉第三段「远程访问」 | 开关默认是开（新建服务时镜像建了 `root@'%'`） |
| 2.2 | 关开关 → 弹确认框 | 文案写明"关闭后只有容器内部能连 root，外部客户端要用业务账号连接" |
| 2.3 | 点「取消」 | 开关保持开，什么都没变 |
| 2.4 | 再关一次，点「关闭」 | 提示"root 远程访问已关闭"，开关变灰 |
| 2.5 | 用 DBeaver 拿 root **从局域网另一台机器**连这个服务 | 被拒（1130 Host is not allowed 或 1045 拒绝访问）。注意：**从 NAS 自己本机**（`127.0.0.1` / SSH 隧道）连可能仍然能连，那是 Docker 端口转发把来源保留成 127.0.0.1 造成的，不算这一版的问题 |
| 2.6 | 用业务账号（非 root）从局域网连 | 正常，说明只收敛了 root |
| 2.7 | 关掉后再打开开关 | 提示"root 远程访问已开启"，开关变亮 |
| 2.8 | 再拿 root 从局域网连 | 能连上，密码与抽屉里显示的一致 |
| 2.9 | 停止服务后再打开抽屉 | 「远程访问」段出现黄色提示"实例未运行，启动后才能查看远程访问设置"，开关**置灰不可点**（不会显示成"已关闭"骗人） |
| 2.10 | 启动服务，重开抽屉 | 提示消失，开关恢复可点且状态正确 |

## 4. 访问来源支持网段

> 前提：先建一个业务账号，或在「用户」抽屉里编辑一个既有账号。

| # | 步骤 | 预期 |
| --- | --- | --- |
| 4.1 | 用户抽屉 → 新建用户 → 权限选「指定 IP」 | 输入框占位符是 `172.16.10.111,172.16.10.0/24`，下方提示写明"IP 或网段" |
| 4.2 | 填 `172.16.10.0/24` 建号 | 建号成功 |
| 4.3 | 用 DBeaver 以 root 执行 `SELECT user, host FROM mysql.user WHERE user='网段账号名';` | Host 是 `172.16.10.0/255.255.255.0`（**前缀被转成了点分掩码**，不是原样的 `/24`） |
| 4.4 | 把网段改成**你这台机器实际所在的网段**（如 `192.168.1.0/24`），保存 | 保存成功 |
| 4.5 | 从同一网段的电脑用该账号连 | 能连（网段内放行） |
| 4.6 | 改成另一个网段（如 `10.99.0.0/24`）保存后，再从你这台电脑连 | 被拒（1130 Host is not allowed），说明网段真的在起作用，不是"填什么都放行" |
| 4.7 | 填 `172.16.10.0/33` 保存 | 报错"掩码不合法，应为 0~32 或 255.255.255.0 这种写法" |
| 4.8 | 填 `172.16.10.0/255.255.255.0` 保存 | 保存成功，列表显示也是点分掩码形式 |
| 4.9 | 一次填两个：`192.168.1.10,192.168.1.0/24` | 保存成功，列表显示"2 个来源" |
| 4.10 | 编辑时删掉其中一个再保存 | 对应的账号记录被删，另一个保留 |

## 7. 这一版故意没做

- **直接在界面里编辑 my.cnf 原文**：后端接口（`GET/PUT /instances/{id}/config/file`、恢复上一版）已经就绪，但**前端还没有入口**，这一版看不到。白名单之外的参数暂时还是改不了。
- root 远程访问只控制 `root@'%'` 这一条账号，**不碰防火墙**：关了之后端口照样开着，只是 root 连不进；要按 IP 限制访问，用业务账号的「访问来源」。
- 「访问来源」不支持主机名（`db.internal` 这类）。MySQL 默认 `skip-name-resolve`，写了也不会生效，所以直接拒绝，别当成缺陷报。
- Host 里的 IP 段数字暂不做 0–255 范围校验（填 `300.1.1.1` 会被 MySQL 自己拒掉）。
- 连接信息抽屉里没有「测试连接」按钮，也没有连接二维码。
- 没有健康检查状态灯、没有监控曲线。

## 8. 出包前跑过的验证

- 前端 `vue-tsc --noEmit` + `vite build` 通过（1661 modules）。
- 后端 `gofmt` / `go vet` / `go test -count=1 ./...` 全绿；本版新增 `roles_test.go`：网段转点分掩码逐档（/0 /8 /16 /24 /32、非法 /33、非法 abc）、`NormalizeHosts` 去重与空值回落、`ValidHost` 接受/拒绝清单。
- 容器冒烟（真 Docker + 真 MySQL 8.4）双架构各 19 项全绿，本版新增 2 项：
  - `访问来源支持网段`：`172.16.30.0/24` 建号后 `mysql.user.Host` 落成 `172.16.30.0/255.255.255.0`；`/33` 在参数层被 400 拒掉。
  - `root 远程访问开关与 root 密码重设`：关闭后 `mysql.user` 里 `root@'%'` 消失、`root@localhost` 保留；再开启时 `root@'%'` 回来；7 位密码与含 `$` 的密码被 400 拒；改成 `NiuSmoke_2026` 后旧密码 1045、新密码能连、连接信息里就是新密码。
- **一个必须知道的平台差异**：macOS 上 Docker Desktop 的端口转发会把来源地址保留成 `127.0.0.1`，MySQL 反解成 `localhost`，所以本机关掉 root 远程后**照样能用 root 连**。Linux 真机是桥接，局域网来源是真实 IP，会被 1130 拒。冒烟因此改成直接查 `mysql.user`，不拿"本机连不连得上"作断言；这条效果只能在真机上验，见 2.5。
