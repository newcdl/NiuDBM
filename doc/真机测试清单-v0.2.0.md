# 牛库管家 v0.2.0 真机测试清单

> 适用包：`niudbm-0.2.0-amd64.fpk`（x86 机器）、`niudbm-0.2.0-arm64.fpk`（ARM 机器）
> 目标：确认**第一个可用版本**在飞牛 fnOS 上装得上、打得开、建得了库、备份能回来。
> 测试方式：按 P0 逐条走完即可判断这一版能不能用；P1 是稳定性与权限，能测就测。

---

## 0. 本次交付是什么

v0.2.0 是第一个**能用**的版本，功能范围：

| 能力 | 说明 |
| --- | --- |
| 建库 | 创建 SQLite 实例，可带初始化 SQL（多条语句按顺序执行，出错整体回退） |
| 浏览 | 实例列表、体积、表数量、表结构（列名/类型/主键/非空/默认值） |
| SQL 控制台 | 单条语句执行；SELECT 结果表格化，写操作返回影响行数 |
| 备份 | 一致性快照（不锁库），生成后自动做完整性校验，附 SHA256 |
| 恢复 | 恢复前自动留一份保护性备份，之后要回退还能选它 |
| 审计 | 建库、改名、删库、写 SQL、备份、恢复、删备份全部留痕 |
| 自检 | 平台自检页，核对目录映射、权限边界、运行身份 |

刻意**没有**做（不要当缺陷报）：MySQL/PostgreSQL/Redis、定时备份、成员权限、导入外部 .db、回收站可视化、资源限制。

技术形态：一个 Go 静态二进制，前端 Vue3 产物内嵌在里面，通过统一网关 `/app/niudbm` 访问，不占宿主端口。

---

## 1. 安装前

1. 确认 CPU 架构，决定装哪个包：

   ```
   uname -m
   ```

   - `x86_64` → 装 `amd64` 包
   - `aarch64` / `arm64` → 装 `arm64` 包

   装错架构会在应用中心启动失败，日志里出现 `Exec format error`。

2. 确认系统版本不低于 manifest 声明：`os_min_version = 1.1.3100`。

3. 校验包完整性（把文件名换成实际路径）：

   ```
   sha256sum niudbm-0.2.0-amd64.fpk
   ```

   与同目录 `niudbm-0.2.0-amd64-SHA256SUMS.txt` 里的值比对。

4. 记住安装前的数据现状，便于确认没有影响其他应用。

---

## 2. 安装

应用中心 → 手动安装（本地安装）→ 选 fpk。

安装脚本会做四件事，任何一步失败都会中止安装并在安装日志里写明原因：

- 架构检查（x86_64 / aarch64）
- 内存 ≥ 512 MB
- 目标分区剩余 ≥ 200 MB
- 创建数据目录：`instances` / `backups` / `trash` / `logs`，并把属主交给应用用户

## 3. P0 验证项（这一版能不能用，就看这 9 条）

### P0-1 应用中心能打开界面

- 操作：应用中心点开「牛库管家」
- 通过：出现左侧导航（概览 / 数据库 / 操作记录）和顶部状态条，页面样式正常（有绿色主色、卡片阴影）
- 失败典型：
  - 白屏 → 多半是 `base` 注入或网关前缀问题
  - 页面能出来但所有数据都是「请求失败」→ 接口前缀问题
  - 一直转圈 → 服务没起来
- 顺带确认：地址栏是 `/app/niudbm`，**没有任何端口号**。如果出现 `:8780` 之类，说明走到端口模式了，不符合设计。

### P0-2 概览页有真实数据

- 通过：能看到「应用 niudbm 0.2.0」「数据库实例 0 个」「运行身份」「CPU 架构」「监听方式 unix:…」「系统」，以及自检统计（通过/需确认/未通过三项数字）
- 点「自检明细」：能看到分组条目，每项有 PASS / WARN / FAIL 标记与说明
- **把 FAIL 项记下来**，这一版最需要你反馈的就是这个

### P0-3 新建一个实例

- 操作：数据库 → 新建实例 → 名称填 `测试库` → 档位选「轻量」→ 初始化 SQL 填：

  ```
  CREATE TABLE notes (id INTEGER PRIMARY KEY, title TEXT NOT NULL);
  INSERT INTO notes (title) VALUES ('第一条');
  ```

  → 创建
- 通过：跳进实例详情，顶部显示「运行中」「sqlite · 轻量」，体积不为 0，显示「1 张表」
- 失败典型：提示「初始化 SQL …」→ 语法问题；提示「实例名已存在」→ 之前残留

### P0-4 SQL 控制台能写能读

- 操作：SQL 控制台 → 输入 `INSERT INTO notes (title) VALUES ('第二条');` → 执行（或 Ctrl+Enter）
- 通过：出现「写入」标记 + 「语句已执行，影响 1 行」+ 耗时毫秒数
- 再输入 `SELECT * FROM notes;` → 执行
- 通过：表格两行，列名是 `id` / `title`
- 护栏确认：执行 `SELECT 1; SELECT 2` 应被拒绝，提示一次只能执行一条语句

### P0-5 表结构能看到

- 操作：表结构 → 点 `notes`
- 通过：列出 `id`（主键）、`title`（非空），类型与建表语句一致

### P0-6 备份能生成，并且落到共享目录

- 操作：备份与恢复 → 说明填「第一次」→ 立即备份
- 通过：列表新增一行，状态「成功」，大小不为 0，类型「手动」
- 关键确认：页面上「备份目录」显示的是**共享目录**路径（形如 `/vol1/…/niudbm/backups`），不是 `/var/apps/niudbm/var/backups`。如果显示的是后者，说明共享目录不可写，需要反馈
- 到文件管理器里按这个路径找一下，应该能看见 `实例ID/2026xxxx-xxxx.db` 文件

### P0-7 恢复能回到备份时刻

- 操作：回到 SQL 控制台，再插一条 `INSERT INTO notes (title) VALUES ('第三条');`（此时 3 行）
- 备份与恢复 → 对刚才那份备份点「恢复」→ 输入实例名 `测试库` → 确认恢复
- 通过：提示恢复成功，并且列表里多出一行类型为「恢复前自动」的备份
- 回 SQL 控制台执行 `SELECT COUNT(*) FROM notes` → **应为 2**（回到备份时的行数）

### P0-8 删除进回收站

- 操作：设置与删除 → 删除实例 → 输入名称 → **不勾选**「保留数据文件」→ 确认
- 通过：返回列表，列表变空
- 检查：数据目录下对应实例的文件夹消失；回收站目录（`/var/apps/niudbm/var/trash`）里出现一个 `实例ID-时间戳` 目录（需要 SSH 才能看到，看不到也不影响结论）

### P0-9 审计有记录

- 操作：操作记录
- 通过：至少能看到「创建实例」「创建备份」「恢复备份」「删除实例」四类，操作者是当前登录用户，结果都是「成功」

## 4. P1 验证项（稳定性与权限）

### P1-1 重启应用后数据还在

- 应用中心停止 → 启动
- 通过：之前建的实例还在列表里，能打开、能查表（注：若在 P0-8 中删掉了，先重建一个）

### P1-2 普通用户只能看不能改

- 用一个**非管理员**的飞牛账号登录，打开牛库管家
- 通过：能看列表与表结构；点「新建实例」会被拒，提示需要管理员
- 如果普通用户连页面都打不开 → 这是入口 `allUsers` 的问题，需要反馈

### P1-3 备份文件能在文件管理器里看到

- 通过：`/vol…/niudbm/backups/<实例ID>/` 下有 `.db` 文件，大小与页面显示一致

### P1-4 卸载不删数据

- 应用中心卸载 → 重新安装
- 通过：实例列表恢复（元数据库在 `var` 下，卸载脚本只清缓存）
- 若数据丢了 → 立刻停止测试并反馈，这是数据安全问题

## 5. 出问题怎么取日志

SSH 登录 NAS 后按顺序看：

1. 服务日志（最常见的问题都在这里）：

   ```
   tail -n 100 /var/apps/niudbm/var/logs/server.log
   ```

2. 平台自检报告（安装 / 升级 / 配置变更时自动生成）：

   ```
   cat /var/apps/niudbm/var/diagnose-report.txt
   ```

3. 安装与启动日志：

   ```
   tail -n 100 /var/apps/niudbm/var/logs/*.log
   ```

4. 服务状态与端口：

   ```
   ls -l /var/apps/niudbm/target/app.sock
   ```

   socket 存在说明服务起来了，网关连不上就是网关侧的问题。

把这四样里相关的内容贴给我，比描述「打不开」有用得多。

## 7. 已知限制（已知且接受，不用报）

- 只支持 SQLite；其他引擎在后续版本
- 没有定时备份，只有手动
- 没有成员与账号体系，写操作一律要求管理员
- 删除后的实例只能人工从回收站目录找回，界面里看不到回收站
- 不能导入已有的 `.db` 文件（下一版补）
- 实例不能「启动/停止」——SQLite 是文件型数据库，没有常驻进程
