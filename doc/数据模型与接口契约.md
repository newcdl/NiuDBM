## 0. 三条底层约定

| 约定 | 含义 | 为什么重要 |
| --- | --- | --- |
| **元数据库是唯一真相** | 实例状态、账号、备份记录全部以 SQLite 为准；引擎真实状态靠"观测"回填，不反向覆盖用户意图 | 避免"界面显示运行中、进程其实已挂"的状态漂移 |
| **长操作一律任务化** | 超过 3 秒的动作全部落 `jobs` 表，接口立即返回任务号 | 页面可关、可重试、可审计，且天然支持进度展示 |
| **身份只从网关来** | 所有接口从 Header 取 `X-Trim-Userid/Username/Isadmin`，**不接受**任何请求体或查询参数里的用户标识 | 防越权，且免自建登录 |

## 1. 两层身份模型（最容易混淆的地方，必须先说清）

产品里有两个完全不同的"用户"概念：

| 层 | 是什么 | 存在哪 | 用来做什么 |
| --- | --- | --- | --- |
| **NAS 用户** | 飞牛系统账号，由网关 Header 带入 | `instance_members` | 决定**谁能在这个界面里操作某个实例** |
| **数据库账号** | 引擎内部的账号（如 `blog_user`） | `accounts` + `grants` | 决定**应用能不能连、能读哪些表** |

关系：一个 NAS 用户可能管理多个数据库账号；一个数据库账号不属于任何 NAS 用户（它是给应用用的）。界面上绝不能用"用户"同时指代两者，文案统一为「成员」与「数据库账号」。

## 2. 元数据库表结构

所有表位于 `var/niudbm.db`（SQLite，WAL 模式）。主键统一用 ULID（可排序、无自增依赖）。

### 2.1 `instances` 实例台账

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PK | ULID |
| `name` | TEXT UNIQUE | 用户可见名，1–32 字符 |
| `engine` | TEXT | `mariadb` / `mysql` / `postgresql` / `valkey` / `sqlite` / `mongodb` |
| `engine_version` | TEXT | 实际使用的版本 |
| `engine_bundle_id` | TEXT FK | 指向 `engine_bundles.id`；`sqlite` 为空 |
| `mode` | TEXT | `managed`（本应用托管）/ `adopted`（纳管外部实例） |
| `status` | TEXT | 见 §3.1 状态机 |
| `status_reason` | TEXT | 非运行态时的人类可读原因 |
| `data_dir` | TEXT | 相对 `var/instances/{id}` 或授权目录的路径 |
| `port` | INTEGER NULL | `sqlite` 为空 |
| `bind_scope` | TEXT | `loopback` / `lan` |
| `bind_cidr` | TEXT NULL | 仅 `lan` 时有值 |
| `profile` | TEXT | `low` / `standard` / `performance` |
| `created_at` / `updated_at` | INTEGER | Unix 毫秒 |
| `last_health_at` | INTEGER NULL | 最近一次健康检查成功时间 |

约束：`mode=adopted` 时 `data_dir`、`engine_bundle_id` 必须为空（不托管文件）；`bind_scope=lan` 时 `bind_cidr` 必填。

### 2.2 `instance_members` 成员授权

| 字段 | 类型 | 说明 |
| --- | --- | --- |

| `role` | TEXT | `operator` / `viewer`（管理员不需入表，由 `isAdmin` 直接判定） |
| `added_by` | TEXT | 操作者 user_id |

### 2.4 `accounts` 数据库账号

| --- | --- | --- |

## 3. 状态机与枚举

### 3.1 实例状态

```
                 ┌──────────────┐
  创建 ──────▶  │ initializing │
                 └──────┬───────┘
                        │ 成功
                 ┌──────▼───────┐   失败   ┌────────┐
                 │   starting   ├────────▶ │ failed │
                 └──────┬───────┘          └───┬────┘
                        │                      │ 重试
                 ┌──────▼───────┐              │
                 │   running    │ ◀────────────┘
                 └──────┬───────┘
                        │ stop
                 ┌──────▼───────┐
                 │   stopping   │──▶ stopped
                 └──────────────┘
```

规则：

- `failed` 必须带 `status_reason`（人话），否则视为缺陷；
- `deleting` 为终态前置，删除过程中禁止任何写操作；
- 状态只能由任务推进，**接口不允许直接 setStatus**。

### 3.2 其他枚举

| 枚举 | 取值 |
| --- | --- |
| 实例模式 | `managed` / `adopted` |
| 绑定范围 | `loopback` / `lan` |
| 资源档位 | `low` / `standard` / `performance` |
| 成员角色 | `operator` / `viewer`（管理员由 isAdmin 派生） |
| 账号状态 | `active` / `locked` |
| 备份类型 | `manual` / `scheduled` / `pre_upgrade` / `pre_restore` |

### 3.3 任务类型

| 类型 | 说明 | 可取消 |
| --- | --- | --- |
| `instance.create` | 建实例（含初始化） | 是（初始化前） |
| `instance.start` / `stop` / `restart` | 生命周期 | 否 |
| `instance.delete` | 删除 | 否 |
| `engine.download` / `engine.import` | 引擎包获取 | 是 |
| `backup.create` / `backup.restore` / `backup.verify` | 备份相关 | 备份是 / 恢复否 |
| `db.import` / `db.export` | 数据搬运 | 是 |
| `account.sync` | 账号权限下发 | 否 |

**并发规则**：同一实例的破坏性任务（restore / delete / upgrade）必须串行；下载类任务全局并发上限 2。

## 4. 索引与保留策略

### 4.1 必要索引

| 表 | 索引 | 目的 |
| --- | --- | --- |
| `instances` | `(status)`、`(engine)` | 列表筛选 |
| `jobs` | `(status, created_at)`、`(target_id)` | 任务中心与轮询 |
| `backup_records` | `(instance_id, started_at DESC)` | 备份列表 |
| `metrics_samples` | `(instance_id, ts DESC)` | 趋势查询 |
| `audit_logs` | `(ts DESC)`、`(target_id)` | 审计检索 |
| `grants` | `(account_id)`、`(database_id)` | 矩阵渲染 |

### 4.2 数据保留

| 数据 | 原始保留 | 聚合保留 | 清理方式 |
| --- | --- | --- | --- |
| 指标采样 | 7 天 | 5 分钟粒度 30 天 | 启动时 + 每日清理 |
| 审计日志 | 180 天（可配） | — | 按时间分批删 |
| 任务记录 | 30 天 | — | 仅删记录，不删关联备份 |
| 备份文件 | 按策略 | — | 超份数/天数即删，删前校验引用 |

**硬规则**：清理任务本身也要写任务记录，避免"数据莫名其妙少了"却查不到。

## 5. 接口契约

### 5.1 基础约定

| 项 | 约定 |
| --- | --- |
| 前缀 | `/app/niudbm/api/v1`（网关相对路径，前端不写死域名） |
| 方法 | 读 `GET`、写 `POST/PATCH/DELETE`，不做 `PUT` 全量覆盖（除授权矩阵） |
| 响应包 | `code`（0 成功）、`message`、`data`、`traceId` |
| 时间 | ISO-8601 UTC 字符串 |
| 分页 | `cursor` + `limit`（默认 20，上限 100），返回 `nextCursor` |
| 幂等 | 写操作接受 `Idempotency-Key` 头；同键 24 小时内返回首次结果 |
| 长任务 | 返回 `202` + `jobId`，前端跳任务中心或就地轮询 |
| 身份 | 只读 Header，**请求体中的 userId 一律忽略** |
| 版本 | 路径带 `v1`；字段只增不减，废弃字段先标记后移除 |

### 5.2 错误码分段

| 区段 | 含义 | 示例 |
| --- | --- | --- |
| `1000x` | 通用 | `10001` 参数非法、`10002` 未授权、`10003` 限流 |
| `2000x` | 实例 | `20001` 实例不存在、`20002` 状态不允许、`20003` 端口冲突 |
| `3000x` | 引擎 | `30001` 包缺失、`30002` 校验失败、`30003` 架构不支持 |
| `4000x` | 库与账号 | `40001` 库已存在、`40002` 账号已存在、`40003` 授权冲突 |
| `5000x` | 备份 | `50001` 目标不可写、`50002` 校验失败、`50003` 恢复被拒 |
| `6000x` | 导入导出 | `60001` 文件不可读、`60002` 编码不兼容 |
| `7000x` | 任务 | `70001` 任务不存在、`70002` 不可取消 |

每个错误码必须绑定一句 `error_hint`（给用户看的下一步），不允许只有码没有话。

## 6. 权限判定矩阵

判定顺序（**短路**）：

1. Header 缺失或不可信 → `10002`
2. `isAdmin=true` → 放行全部
3. 查 `instance_members`：`operator` 可写常规操作，`viewer` 只读
4. 不在成员表 → 仅允许 `GET /instances`（返回空列表）与申请入口
5. 高风险动作（删实例、删库、恢复、开外网）额外要求 `isAdmin=true`

| 接口组 | 管理员 | operator | viewer | 非成员 |

## 7. 兼容与演进

| 规则 | 说明 |
| --- | --- |
| 只增不改 | 新增字段必须有默认值；不得改变已有字段语义 |
| 枚举扩展 | 新值只追加，不复用旧值，前端遇到未知值降级为"未知"而非报错 |
| 废弃流程 | 先标记 `deprecated` 并保留一个版本，再移除 |
| 迁移可回滚 | `schema_migrations` 记录双向版本，升级前自动备份元数据库 |
| 契约测试 | 前后端共用同一份字段清单，接口变更必须同步更新本文档 |
