# 牛库管家（NiuDBM）骨架验证指南

> 配套文档：[权限与平台核对清单](./权限与平台核对清单.md) ｜ [产品与技术方案](./牛库管家-NiuDBM-产品与技术方案.md) ｜ [数据模型与接口契约](./数据模型与接口契约.md)
>
> 对应版本：`niudbm 0.1.0`（自检包，**不含数据库功能**）

---

## 1. 这个包是什么

一个能装进 fnOS、能在应用中心里打开的**最小应用**，唯一用途是把核对清单里"只能靠真机行为兑现"的假设一条条测掉。

它不做数据库管理，只做三件事：

1. 安装后把平台注入的 `TRIM_*` 变量、目录软链、真实落盘路径打印出来；
2. 主动尝试越权写入（`/etc`、其他应用目录、`docker.sock`），验证权限边界是否真的生效；
3. 提供 `start / stop / status`，验证平台对生命周期与退出码的调用语义。

---

## 2. 为什么是 shell + CGI，而不是 Go + 网关

这一点必须先说清，否则会误以为架构改了。

| 项 | 骨架现状 | 最终形态 | 差异原因 |
| --- | --- | --- | --- |
| 后端 | `index.cgi`（shell，每次请求启动） | Go 单二进制 + Unix Socket | 本机没有 Go 工具链，且骨架目标是**验证平台**而非实现功能；CGI 零编译、零依赖，能把变量与权限结果直接吐到页面上 |
| 入口 | `/cgi/ThirdParty/niudbm/index.cgi` | 统一网关 `/app/niudbm` | CGI 入口恰好可以反向验证"不声明 `service_port` 也能装能用"（P-08） |
| 数据库 | 无 | SQLite 元数据库 | 骨架还没有需要持久化的状态 |
| 启停 | 心跳进程占位 | 真实服务进程 | 只为验证 `start/stop/status` 语义（P-21） |

**结论**：骨架的目录结构、`manifest`、`config/privilege`、`config/resource`、生命周期脚本命名与最终版完全一致，只有 `app/` 内的实现是临时替身。后续把 `app/ui/index.cgi` 换成 Go 服务 + `app/ui/config` 改为网关写法即可，**不需要重做打包结构**。

## 3. 目录结构

```
niudbm/
├── manifest                 应用元信息（不声明 service_port、platform=all）
├── config/
│   ├── privilege            run-as=package，包用户 niudbm，不加任何特权组
│   └── resource             data-share: niudbm/backups、niudbm/exports
├── cmd/                     9 个生命周期脚本，全部 bash
│   ├── install_init         前置检查：架构、内存、目标分区空间
│   ├── install_callback     初始化目录、写默认配置、生成首份自检报告
│   ├── main                 start / stop / status（status 退出码 0 运行、3 停止）
│   ├── upgrade_init         升级前备份元数据库，失败即中止
│   ├── upgrade_callback     记录版本、重跑自检
│   ├── uninstall_init       只记录，不删除
│   ├── uninstall_callback   仅清缓存，用户数据全部保留
│   ├── config_init          记录授权目录变更
│   └── config_callback      落盘授权目录、重跑自检
├── app/
│   ├── ui/
│   │   ├── config           入口声明（url + type=iframe）
│   │   ├── index.cgi        自检页入口
│   │   └── images/          64 / 256 图标
│   └── server/
│       └── diagnose.sh      自检脚本（文本与 HTML 两种输出）
├── ICON.PNG                 64×64
├── ICON_256.PNG             256×256
└── wizard/                  预留（当前为空，格式待真机确认）
```

图标源文件在 `design/icon.svg`，改色重生成即可。

## 4. 打包

```bash
./scripts/build.sh          # 只做静态检查：脚本语法、JSON、manifest 必填项、图标、可执行位
./scripts/build.sh --pack   # 检查通过后调用 fnpack 打包
```

`build.sh` 会主动拦截三类常见错误：

- 声明了 `service_port`（当前架构不应声明）；
- `platform=all` 却混入架构相关二进制；
- 脚本忘记 `chmod +x`（这是最容易被忽略、装上去才报错的坑）。

`fnpack` 需从飞牛开发者中心获取，本机尚未安装。

## 5. 怎么看结果

**路径一：应用中心 → 牛库管家 → 打开**，直接看到自检页（HTML）。

**路径二：SSH 到 NAS 手工执行**

```bash
/bin/bash /var/apps/niudbm/target/server/diagnose.sh
```

**路径三：读安装时自动生成的报告**

```bash
cat /var/apps/niudbm/var/diagnose-report.txt
```

三种方式内容一致，都按 `通过 / 需确认 / 未通过` 三态输出。**未通过项必须处理完再进入下一阶段。**

## 6. 自检项 → 核对项映射

| 自检页项目 | 对应核对项 | 通过意味着什么 |
| --- | --- | --- |
| 运行身份 | P-05 | 进程不是 root，最小权限前提成立 |
| 身份与声明一致 | P-05、P-07 | `TRIM_UID` 与实际 uid 一致，脚本拿到的身份可信 |
| 数据/配置/临时/安装/用户目录 | P-02 | `target/etc/var/tmp/home` 软链与变量一一对应且可写 |
| 写入 `/etc` | P-03、P-05 | 系统目录越权被拒绝 |
| 写入其他应用根目录 | P-03、P-16 | 应用间隔离有效 |
| 访问 Docker Socket | P-03、P-06 | 未获得 Docker 控制权（这是原生方案的关键前提） |
| 共享目录 | P-12、P-13 | `data-share` 已创建、路径变量正确、应用用户可写 |
| 架构 | P-17 | 当前架构与声明一致 |
| C 运行库 | P-18 | 记录 glibc 版本，作为引擎分发基线 |
| 端口池 | P-19 | 33000+ 未被占用（**尚未验证是否对外暴露**） |
| 平台变量注入 | P-02、P-07 | 变量集合与文档一致 |
| `TRIM_API_TOKEN` | P-15 | 令牌已注入（不打印内容） |
| 安装标记 / 服务心跳 | P-20、P-21 | 生命周期脚本被正确调用 |

## 7. 这个包**不能**验证的项

必须诚实列出，避免误判"装上了就等于方案成立"：

| 核对项 | 为什么测不了 | 怎么补 |
| --- | --- | --- |
| P-01 安装位置可选 | 需要装两次（系统盘 / 数据卷）对比 | 真机各装一次，记录落盘路径 |
| P-04 升级保留数据 | 需要两个版本才能升 | 发 0.1.1 后从 0.1.0 升级验证 |
| P-08 网关入口 | 本包走 CGI，未走统一网关 | 后续把 `app/ui/config` 改为 `gatewayPrefix` + `gatewaySocket` 再测 |
| P-09 / P-10 Header 与 WebSocket | 同上，CGI 拿不到网关 Header | 同上 |
| P-11 远程访问 | 需要 FN Connect / 反代环境 | 真机远程各走一遍 |
| P-14 文件选择器 | `micro_app=false`，未引入 JS SDK | 需要开 `micro_app` 并接 SDK |
| P-23 断电恢复 | 需要真实断电 | 真机做 kill -9 与断电各一次 |
| P-24 / P-25 上架合规 | 需完整上架走一遍 | 提交前人工复核三个配置文件 |

## 8. 骨架里故意留的待确认点

| 项 | 现状 | 待确认内容 |
| --- | --- | --- |
| `desktop_applaunchname` | **已移除** | 该字段指向可执行的启动程序，骨架没有二进制。需确认：只有 `desktop_uidir` 时桌面图标能否打开界面 |
| `app/ui/config` 的 url | 用 `/cgi/ThirdParty/niudbm/index.cgi` + `type=iframe` | 入口是否还需要 `port` 字段；路径是否需要尾斜杠 |
| `wizard/` | 空目录 | `fnpack` 是否强制要求安装向导；若不强制则保持为空直到需要"选择安装位置" |
| `os_min_version=1.1.3100` | 按网关最低版本填写 | CGI 方式是否需要这么高的系统版本，可尝试下调 |
| `platform=all` | 因包内无架构相关二进制 | 后续引入 Go 二进制后必须拆成 x86 / arm 两个包 |

## 9. 下一步

1. 安装 `fnpack`，执行 `./scripts/build.sh --pack` 出包；
2. 在 D1（x86）装上，打开自检页，把 `未通过` 项逐条处理；
3. 在 D2（arm）重复一次，重点看 P-17、P-18；
4. 自检全绿后，把 `app/` 换成 Go 服务并切到统一网关，重新验证 P-08 ~ P-11。

**不要跳过第 2 步直接写业务代码**——目录与权限若与预期不符，业务代码里的路径假设会全部作废。
