# 牛库管家 v0.1.3 真机测试清单 · 按库管理

> 适用包：`niudbm-0.1.3-amd64.fpk`（x86）、`niudbm-0.1.3-arm64.fpk`（ARM）
> 上一版 0.1.2 的 P0 主线（部署、连接、存储、删除）仍然要过一遍，清单见 [真机测试清单-v0.1.2](./真机测试清单-v0.1.2.md)；这一版重点验下面四件事。
> 安装：应用中心手动安装，直接覆盖 0.1.2，不用卸载。

---

## 1. 服务列表改成卡片

| # | 步骤 | 预期 |
| --- | --- | --- |
| 1.1 | 打开「数据库」页 | 每个服务是一张卡片，不是表格行 |
| 1.2 | 看卡片内容 | 名称、MySQL 版本、状态胶囊、端口、表数、体积、备份份数都在卡里 |
| 1.3 | 卡片底部操作 | 管理 / 库与账号 / 配置 / 停止（或启动）/ 删除，五个都在卡里，不用横向滚动 |
| 1.4 | 刚部署完一个服务后回到列表 | 新卡片有高亮边框，一眼能找到 |
| 1.5 | 把手机横过来或缩窄浏览器窗口 | 卡片自动换行成一列，不出现横向滚动条 |
| 1.6 | 部署失败的服务 | 卡片显示失败原因，操作只剩「部署日志」「删除」 |
| 1.7 | 搜索框输入服务名 | 卡片过滤生效 |

## 2. 概览的连接信息（这一版改动最大，重点验）

| # | 步骤 | 预期 |
| --- | --- | --- |
| 2.1 | 进任一服务 → 概览 | 「连接信息」里用户显示 **root**，密码能显示/隐藏 |
| 2.2 | 看有没有「数据库」这一行 | **没有了**。一个服务下有多个库，不该给一个默认库 |
| 2.3 | 点地址后面的「复制」 | 复制到的是 `IP:端口`，粘到别处核对一致 |
| 2.4 | 点用户名、密码后的复制 | 各自复制成功 |
| 2.5 | 看「连接串」 | 形如 `mysql://root:密码@192.168.x.x:33001/`，**含密码** |
| 2.6 | 复制连接串，粘进 DBeaver / Navicat / TablePlus 的连接串解析 | 能直接解析出主机、端口、root、密码并连上 |
| 2.7 | 密码里如果有 `@`、`:`、`/`（可以在部署时故意设一个） | 连接串里这些字符被转义，粘进客户端仍能连上，不会把主机名截断 |
| 2.8 | 用 root 连上后建库、建账号 | 都成功（root 就是给管理操作用的） |

## 3. 「数据库」与「用户」合成一页

| # | 步骤 | 预期 |
| --- | --- | --- |
| 3.1 | 看页签 | 只有一个「数据库与账号」，不再有单独的「用户」 |
| 3.2 | 进这一页 | 上方是库列表，下方是账号列表 |
| 3.3 | 在某个库那一行点「建账号」 | 弹出建号表单，标题写明是给哪个库建 |
| 3.4 | 填账号名、密码（点「随机」生成）、权限选读写，创建 | 创建成功；账号出现在下方列表 |
| 3.5 | 用这个新账号连接，访问该库 | 能连上、能读写该库 |
| 3.6 | 同一账号访问**别的**库 | 被拒（1044）——账号只授这一个库 |
| 3.7 | 给一个不存在的库建账号（可先用两个标签页制造：一页留着旧库名） | 提示「库不存在，先建库再建账号」，不会建出空授权账号 |
| 3.8 | 服务停止状态下点「建账号」 | 按钮置灰并说明先启动 |
| 3.9 | 老链接 `?tab=users`（如果书签里还有） | 自动落到「数据库与账号」，不白屏 |

## 5. 这一版故意没做（别当缺陷报）

- 镜像页仍然只能列出本地镜像，没有拉取/导入/删除入口（下一版 0.1.4）。
- 没有容器健康检查与状态灯、没有连接二维码。
- 定时备份策略仍只备默认库，不能按库配。
- 用户列表是服务级的一览，不能按库筛选查看"哪些账号能进这个库"（要看得靠建号时的记录，或进客户端查 `information_schema`）。

## 6. 出包前跑过的验证

- `gofmt` / `go vet` / `go test -count=1 ./...` 全绿
- 前端 `vue-tsc --noEmit` + `vite build` 通过
- 容器内冒烟（真 Docker + 真 MySQL 8.4）14 项全绿，新增断言：
  - 连接信息 `"user":"root"` 且不含 `"database"`
  - 在 `shop` 库上建账号返回 `"database":"shop"`
  - 按库备份成功、记录带库名、备份文件里**没有**混进默认库
  - 不传库名时落到默认库，记录写 `"database":"app"`
- 冒烟脚本自身修了一个坑：中途失败时容器会一直留着（unless-stopped），现在按"跑之前的快照"做差集清理，只删本次造出来的容器与卷。
