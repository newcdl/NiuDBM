# 牛库管家 v0.1.4 真机测试清单 · 空服务起步 + 多库授权

> 适用包：`niudbm-0.1.4-amd64.fpk`（x86）、`niudbm-0.1.4-arm64.fpk`（ARM）
> 直接覆盖 0.1.3，不用卸载。
> **升级注意**：已经有 `app` 库的旧服务照旧能用，只是那个库不再有"默认库"光环——现在它和别的库一样能删。
> 这一版重点验四件事：服务建出来是空的、列表能切卡片、库列表能看到授权用户、用户抽屉能按库授权。

---

## 1. 新建服务不再自带 app 库（破坏性变更，先验这条）

| # | 步骤 | 预期 |
| --- | --- | --- |
| 1.1 | 部署一个新服务，完成后进「数据库与账号」 | 库列表是空的，提示"还没有数据库"，**没有 app 库** |
| 1.2 | 概览的「表数」 | 显示 0（不是报错） |
| 1.3 | 建一个库 `shop` | 成功，库列表出现 `shop` |
| 1.4 | 再建一个库 `report` | 两个库并存，各自表数/大小独立 |
| 1.5 | 删除 `shop` | 允许删除（不再有"默认库不能删"） |
| 1.6 | 删除 `mysql` 这类系统库（只能走 API 或界面不存在该入口） | 被拒绝，提示引擎自带的库不能删 |
| 1.7 | 备份页 | 建库之前：下拉为空、备份按钮置灰；建库之后：能选到库 |

| 4.10 | 再编辑，移除 `shop` 的授权 | 保存后该账号连 `shop` 被拒（1044），`report` 仍能读 |

## 5. 多库授权不会被"一把收光"（这版修的坑）

| # | 步骤 | 预期 |
| --- | --- | --- |
| 5.1 | 账号 A 授 `shop` 只读 + `report` 只读 | 两个库都能读 |
| 5.2 | 只把 `shop` 改成读写 | 保存后 `shop` 能写、`report` 仍只有只读（没被连带清空） |
| 5.3 | 把 `shop` 改成"无权限" | `shop` 连不上（1044），`report` 不受影响 |
| 5.4 | 服务里删掉 `report` 库 | 账号照样能用 `shop`，抽屉里该账号的 `report` 授权自然消失 |

## 7. 这一版故意没做

- 镜像页仍只能列出本地镜像，没有拉取/导入/删除（下一版 0.1.5）。
- 没有健康检查与状态灯、没有连接二维码。
- 账号没有"描述/备注"字段（截图里那种），也没有按库筛选账号的独立页面——搜索框输入库名可以代替。
- 密码不可回显（只存密文），只有"重设"，没有"查看"。
- 定时备份策略仍是服务级，不能按库单独配（执行时会把每个库各备一份）。

## 8. 出包前跑过的验证

- `gofmt` / `go vet` / `go test -count=1 ./...` 全绿；前端 `vue-tsc` + `vite build` 通过。
- 容器内冒烟（真 Docker + 真 MySQL 8.4）15 项全绿，新增断言：
  - 新服务 `GET /databases` 返回空列表（没有 app 库）
  - 库列表带 `"users":["reader"`（授权用户列的数据来源）
  - 一个账号 PATCH 成两个库后，返回里能读到 `"database":"report"`
  - 给不存在的库建账号返回 404；删 `mysql` 返回 400
  - 不传库名建备份返回 400（没有默认库兜底）
  - 真实 TCP 探针改成连 `shop` 库，读写/只读/无权限矩阵仍成立
