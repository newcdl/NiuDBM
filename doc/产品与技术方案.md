# 牛库管家产品与技术方案

## 定位

牛库管家是飞牛 NAS 上的多引擎数据库管理与协作应用，核心是“接入、创建、管理、备份和授权”，不是 SQL 开发工具。

目标用户：

- 在 NAS 上运行网站、自建应用或开发环境的个人用户。
- 需要统一管理多个数据库的小型开发团队。
- 希望把数据库、账号、备份和审计集中在一个界面里的 NAS 管理员。

## 产品边界

包含：

- 已有数据库接入。
- Docker 托管数据库创建。
- 数据库、集合、账号、角色和授权。
- 配置文件、运行状态、部署日志和诊断。
- 备份、恢复、任务和审计。
- 服务级成员权限。

不包含：

- SQL IDE、表结构设计器、ETL。
- 通用 Docker 管理器。
- 跨机器数据库集群纳管。
- 替代专业数据库客户端。

## 数据模型

`instances` 同时保存托管服务和外部连接：

- `mode=managed`：由本应用创建和管理容器。
- `mode=external`：用户已有数据库，只保存连接和凭据。
- `engine`：`mysql`、`postgres`、`mongodb`。
- `capabilities`：由后端返回当前服务实际支持的能力，前端不按引擎猜按钮。

配套对象：

- 逻辑数据库/集合。
- 数据库账号与库级授权。
- 备份记录与定时策略。
- 服务成员与角色。
- 持久化任务和审计记录。

## 权限

- NAS 管理员：管理全部服务和全局配置。
- 服务管理员：管理指定服务和成员。
- 运维者：启停、建库、账号、备份和导入导出。
- 只读成员：只能查看被授权服务；敏感凭据不回传。

## 引擎适配

- `mysqlctl`：MySQL 与 MariaDB，区分版本、字符集、配置和备份语法。
- `pgctl`：PostgreSQL 15/16/17，读取真实 `pg_settings` 和配置文件。
- `mongoctl`：MongoDB 6/7/8，使用原生驱动、角色模型和 `mongodump` / `mongorestore`。

托管能力与外部能力分离，外部数据库不会被错误显示为可启停容器。

## 前端

- PC：侧栏导航、紧凑表格和高密度管理界面。
- 手机：底部导航、卡片列表和底部操作面板。
- 路由：`/overview`、`/databases`、`/databases/:id/:tab`、`/backups` 等。
- 页面优先展示异常、服务状态和可执行操作，不做营销式大屏。

## 飞牛接入

- 由飞牛网关透传身份 Header。
- 应用通过 `/app/niudbm` 挂载。
- 服务监听应用目录下的 `app.sock`。
- 托管服务依赖 Docker 官方镜像，数据库数据不进入安装包。
